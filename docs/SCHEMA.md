# Schema

## `data/agentic_coverage.csv` (main dataset)

One row per O\*NET task. 18,796 rows.

| Column | Type | Notes |
|--------|------|-------|
| `task_id` | int | O\*NET task identifier. 18,796 distinct values, one per row. |
| `occupation` | string | O\*NET occupation title the task belongs to. |
| `task_text` | string | Full O\*NET task statement, verbatim from the source taxonomy. |
| `coverage` | float [0.00, 1.00] | Fraction of the task a current autonomous AI agent could complete end to end, on its own, with no human stepping in to act, be present, decide, or take responsibility. `1.00` = fully agent-completable unaided; `0.00` = the agent cannot meaningfully complete any of it alone. Scored to 2 decimals. |
| `rationale` | string | Short free-text justification for the score (e.g. "requires physical presence at meetings", "pure text analysis"). One clause, not a full explanation. |

### What `coverage` is and isn't

- It is a judgment of **autonomous, unaided completion** — an agent gets no credit
  for "could help a human do this."
- It is **not** a capability score. A task can require abilities a model has
  (e.g. legal reasoning) yet still score low, because completing it end to end
  needs a human to hold legal authority, be physically present, or be accountable.
  See [`../INSTRUMENT.md`](../INSTRUMENT.md) and
  [`../scripts/LABELING_SPEC_COVERAGE.md`](../scripts/LABELING_SPEC_COVERAGE.md)
  for the exact instrument and calibration anchors used to produce these scores.
- It reflects one rater's (the model's) judgment per task, produced by a single
  consistent method across the full corpus — not an ensemble or a majority vote.

### Known calibration property

Coverage scores are validated as a **ranking** (Spearman ρ = 0.884 vs. a human
panel, stable across annotator subsets) but are **conservative in absolute
level** — on average 0.147 lower than independent human raters on the same
tasks. See [`../validation/RESULTS.md`](../validation/RESULTS.md) for the full
validation and a suggested linear correction for users who need calibrated
absolute values rather than relative ordering.

## Related, non-released files

- `validation/audit_scores_200.csv` — the de-identified human panel scores behind
  the validation numbers. **Not released** (see `.gitignore` and
  [`../validation/README.md`](../validation/README.md)); regenerated by
  maintainers from a raw export that carries annotator PII.
- `results/ratings_rater{1..4}.csv` — the earlier 100-task LLM-panel pilot that
  motivated this release. Distinct from, and not part of, the human validation
  above.
